# NCM 格式与解密原理

记录 `.ncm` 的文件结构、密钥推导和音频还原过程，供以后维护参考。

## 一、文件结构

```
偏移        长度        内容
─────────────────────────────────────────────
0           8           魔数 "CTENFDAM"
8           2           保留
10          4           密钥长度 key_len (小端)
14          key_len     加密的密钥数据
14+key_len  4           元数据长度 meta_len
...         meta_len    元数据（歌名、封面等，XOR 0x63 + base64 + AES）
...         4           音频 CRC
...         5           保留
...         4           封面图长度 img_len
...         img_len     封面图（JPEG/PNG）
...         剩余        加密的音频数据
```

## 二、密钥推导

### 1. 解出中间密钥

密钥数据每个字节先与 `0x64` 异或：

```python
key_data = bytes(b ^ 0x64 for b in raw[14:14 + key_len])
```

再用固定密钥做 AES-128-ECB 解密：

```
AES 密钥: b"hzHRAmso5kInbaxW"   （16 字节，网易云客户端里写死）
```

### 2. 去掉填充与前缀

AES 结果末尾是 PKCS7 填充（最后一个是填充长度），去掉后得到一个以固定字符串开头的明文：

```
b"neteasecloudmusic" + <真正的音频密钥>
```

去掉前 17 个字节，剩下的就是音频密钥。

## 三、音频还原

音频数据不是标准加密算法，而是一个**变形的 RC4**。

### 1. KSA：由密钥生成替换表

```python
box = bytearray(range(256))
last = 0
for i in range(256):
    c = box[i]
    last = (c + last + key[i % len(key)]) & 0xFF
    box[i] = box[last]
    box[last] = c
```

### 2. PRGA：生成密钥流并异或

```python
for i in range(len(audio)):
    j = (i + 1) & 0xFF
    audio[i] ^= box[(box[j] + box[(box[j] + j) & 0xFF]) & 0xFF]
```

注意这里和标准 RC4 不同：没有 `i` 参与索引，而是用 `i+1` 直接作为下标。

## 四、格式判断

解密后的前 4 字节：

| 开头 | 格式 |
|---|---|
| `fLaC` | FLAC（无损） |
| `ID3` 或 `0xFF 0xFB` | MP3 |

程序按这个决定输出扩展名。

## 五、常见问题

**解出来是乱码 / 播放器打不开**

- 密钥推导错了（检查 `PREFIX` 是否正确剥离）
- 或者文件不是完整的 ncm（下载中断）

**能不能转成 mp4**

不能。`.ncm` 里是**音频**，不是视频。解密结果是 mp3/flac。
真要做成视频，需要用 ffmpeg 把音频和封面图合成：

```bash
ffmpeg -loop 1 -i cover.jpg -i song.mp3 -shortest -c:v libx264 -c:a aac out.mp4
```
